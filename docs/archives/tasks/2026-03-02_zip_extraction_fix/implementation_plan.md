# ZIP展開処理の刷新（ランダムアクセス方式）実装計画

## 背景と目的
従来の `fflate.Unzip` を使ったストリーミング方式では、特定の条件（非Deflate圧縮や特定のバイナリパターン）において、画像データの一部がZIPヘッダーと誤認される「同期ずれ」が発生し、展開エラーや文字化け（データの破損）を招いていました。これを解決するため、目録を先に読み込み、必要な箇所をピンポイントで抽出する「ランダムアクセス方式」へ移行します。

## 実装の詳細
### 1. ZIP目録（EOCD）の解析
- ファイル末尾から EOCD (End of Central Directory) を検索。
- セントラルディレクトリのオフセットとサイズを取得。

### 2. セントラルディレクトリの読み込み
- 目録全体を読み込み、含まれる全ファイルのリスト（パス、圧縮方式、サイズ、データのオフセット）を構築。
- この時点でファイル総数が確定するため、進捗を 0% から正確に計算可能。

### 3. 個別ファイルの抽出と展開
- `zipFile.slice(offset, length)` を使用し、各ファイルのデータ領域のみを取得。
- `fflate.inflateSync` （Deflate時）または生のバイナリ（Store時）として展開。
- File System Access API を使用して、逐次ストレージに書き出し。

### 4. 進捗管理の刷新
- 従来の「読み込みバイト数ベース」から「ファイル数ベース」に変更。
- 各ファイルの処理完了ごとにメーターを更新し、滑らかな進捗を実現。

## 期待される効果
- **堅牢性**: バイナリパターンの誤認が物理的に発生しなくなり、全ての有効なZIPファイルを正しく展開可能。
- **UI応答性**: 展開開始と同時に進捗が動き出し、ユーザーが「止まっている」と感じる不安を解消。
- **低メモリ**: 大容量ZIPでも、処理中のファイル1つ分と目録のみをメモリに保持するため安全。
