# 実装計画: ZIPランダムアクセス展開への刷新

## 1. 現状の課題
- **ストリーミングの不安定性**: `fflate.Unzip` (Stream) 方式では、画像バイナリの中にZIPヘッダーと誤認されるデータが含まれると同期がずれ、文字化けや展開失敗が発生する。
- **UIレスポンス**: 前回の修正で改善したものの、依然として目録の解析と進捗の開始にラグを感じる場合がある。

## 2. 新しいアプローチ
ZIPファイルの構造（末尾に目録がある）を利用した「ランダムアクセス展開」を実装します。

### ステップ
1.  **目録の先読み**: ZIPファイルの末尾（EOCD）をシークし、セントラルディレクトリ（目録）を読み取ります。
2.  **ファイル情報の抽出**: 全ファイルのパス、圧縮方法、圧縮後サイズ、オフセットを取得します。
3.  **個別解凍・保存ループ**:
    - 全ファイル数が確定した状態でループを開始。
    - 各ファイルごとに `zipFile.slice(offset, end)` で必要なデータだけを取り出す。
    - `fflate.inflateSync` (または `UnzipPassThrough`) で個別に解凍。
    - `WritableStream` でディスクに即座に書き出し。
4.  **進捗表示**: 「(現在のファイルインデックス / 総ファイル数) * 100」で、開始直後から正確にメーターを更新します。

## 3. 期待される効果
- **堅牢性**: 仕様に基づき位置を指定して読み込むため、データの誤認識（文字化け）が物理的に発生しません。
- **メモリ効率**: メモリに乗るのは「目録データ」と「現在処理中の1ファイル分」のみであり、1GB超のZIPでもクラッシュしません。
- **UX**: メタデータの読み込みは一瞬で終わるため、展開開始と同時に進捗が動き始めます。
